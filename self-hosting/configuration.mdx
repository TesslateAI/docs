## Overview

All configuration for Tesslate Studio is managed through environment variables, typically stored in a `.env` file in the project root. This page documents every available variable, organized by category, with clear labels for which are **required** and which are **optional**.

To get started, copy the example file:

```bash
cp .env.example .env
```

Then edit `.env` with your preferred text editor.

<Info>
  After changing any environment variable, restart the affected service for the change to take effect:
  ```bash
  docker compose restart orchestrator
  ```
</Info>

## Required Variables

These variables **must** be set for Tesslate Studio to start. Without them, the orchestrator will fail on boot.

### Application Secrets

<ParamField path="SECRET_KEY" type="string" required>
  Used for JWT token signing, session encryption, and Fernet encryption of stored credentials (GitHub tokens, deployment OAuth tokens). Must be a long, random string. Never reuse this across environments.
</ParamField>

**Generate a secure key:**
```bash
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

**Example:**
```env
SECRET_KEY=dGhpcyBpcyBhIHNlY3JldCBrZXkgZm9yIGRlbW8gcHVycG9zZXM
```

<Warning>
  If you change `SECRET_KEY` on a running instance, all existing JWT tokens and encrypted credentials will become invalid. Users will need to log in again, and OAuth connections will need to be re-authorized.
</Warning>

### AI / LLM Configuration

<ParamField path="LITELLM_API_BASE" type="string" required>
  The base URL of your LiteLLM proxy or compatible API endpoint. This is where the orchestrator sends all LLM requests.
</ParamField>

<ParamField path="LITELLM_MASTER_KEY" type="string" required>
  Authentication key for the LiteLLM proxy. Used by the backend to authorize requests.
</ParamField>

```env
LITELLM_API_BASE=https://your-litellm-proxy.com/v1
LITELLM_MASTER_KEY=sk-your-litellm-master-key
```

<Accordion title="Using direct provider API keys instead of a LiteLLM proxy?">
  If you are running a LiteLLM proxy that routes to provider APIs, configure the provider keys on the proxy itself. Tesslate Studio communicates only with the LiteLLM endpoint; it does not send keys directly to OpenAI or Anthropic.

  If you run the built-in LiteLLM instance (included in some deployment configurations), you can set provider keys as environment variables on that service:

  ```env
  OPENAI_API_KEY=sk-your-openai-key
  ANTHROPIC_API_KEY=sk-your-anthropic-key
  ```
</Accordion>

## Database Configuration

<ParamField path="DATABASE_URL" type="string" default="postgresql+asyncpg://tesslate:tesslate@postgres:5432/tesslate">
  PostgreSQL connection string using the `asyncpg` driver. For Docker Compose, the default value connects to the bundled PostgreSQL container. For production, point this at a managed database (Amazon RDS, Supabase, etc.).
</ParamField>

<ParamField path="POSTGRES_PASSWORD" type="string" default="dev_password_change_me">
  Password for the PostgreSQL container (Docker Compose only). This value is used both to initialize the database and in the `DATABASE_URL`.
</ParamField>

<ParamField path="POSTGRES_USER" type="string" default="tesslate">
  PostgreSQL username (Docker Compose only).
</ParamField>

<ParamField path="POSTGRES_DB" type="string" default="tesslate">
  PostgreSQL database name (Docker Compose only).
</ParamField>

<Tabs>
  <Tab title="Docker Compose (local)">
    ```env
    # The default works out of the box.
    DATABASE_URL=postgresql+asyncpg://tesslate:tesslate@postgres:5432/tesslate
    POSTGRES_PASSWORD=dev_password_change_me
    ```
  </Tab>

  <Tab title="External / Managed Database">
    ```env
    DATABASE_URL=postgresql+asyncpg://admin:StrongPassword123@db.example.com:5432/tesslate
    # POSTGRES_PASSWORD is not needed when using an external database.
    ```
  </Tab>

  <Tab title="AWS RDS">
    ```env
    DATABASE_URL=postgresql+asyncpg://tesslate:STRONG_PASSWORD@tesslate-db.xxxx.us-east-1.rds.amazonaws.com:5432/tesslate
    ```
  </Tab>
</Tabs>

<Warning>
  Always change the default password in production. The Docker Compose default is for local development only.
</Warning>

## Authentication & Security

<ParamField path="APP_DOMAIN" type="string" default="localhost">
  The domain where Tesslate Studio is hosted, without protocol. Used for CORS configuration, cookie scoping, and generating project URLs.
</ParamField>

<ParamField path="COOKIE_DOMAIN" type="string" default="">
  Domain for setting authentication cookies. Leave empty for localhost. For production, prefix with a dot to cover subdomains (e.g., `.studio.yourcompany.com`).
</ParamField>

<ParamField path="COOKIE_SECURE" type="boolean" default="false">
  Set to `true` when using HTTPS in production. This ensures cookies are only sent over secure connections.
</ParamField>

<ParamField path="CORS_ORIGINS" type="string" default="">
  Comma-separated list of allowed origins for CORS. The orchestrator also dynamically allows `APP_DOMAIN` and its subdomains.
</ParamField>

```env
# Local development
APP_DOMAIN=localhost
COOKIE_DOMAIN=
COOKIE_SECURE=false
CORS_ORIGINS=http://localhost:3000,http://localhost:5173

# Production
APP_DOMAIN=studio.yourcompany.com
COOKIE_DOMAIN=.studio.yourcompany.com
COOKIE_SECURE=true
CORS_ORIGINS=https://studio.yourcompany.com
```

### CSRF Protection

Tesslate Studio uses a double-submit cookie pattern for CSRF protection. This is handled automatically; no configuration is needed. The CSRF token is set in a JavaScript-readable cookie, and the frontend sends it back in the `X-CSRF-Token` header.

### Encryption

<ParamField path="DEPLOYMENT_ENCRYPTION_KEY" type="string">
  Optional Fernet key for encrypting deployment provider credentials (Vercel, Netlify, Cloudflare OAuth tokens). If not set, derived from `SECRET_KEY`.
</ParamField>

## OAuth Providers (Social Login)

Configure OAuth for GitHub and Google login. Without these, only email/password authentication is available.

<Tabs>
  <Tab title="GitHub">
    <ParamField path="GITHUB_CLIENT_ID" type="string">
      GitHub OAuth application client ID.
    </ParamField>

    <ParamField path="GITHUB_CLIENT_SECRET" type="string">
      GitHub OAuth application client secret.
    </ParamField>

    <ParamField path="GITHUB_OAUTH_REDIRECT_URI" type="string">
      Callback URL registered in your GitHub OAuth app settings.
    </ParamField>

    ```env
    GITHUB_CLIENT_ID=your-github-client-id
    GITHUB_CLIENT_SECRET=your-github-client-secret

    # Local development
    GITHUB_OAUTH_REDIRECT_URI=http://localhost/api/auth/github/callback

    # Production
    GITHUB_OAUTH_REDIRECT_URI=https://studio.yourcompany.com/api/auth/github/callback
    ```

    <Info>
      Create a GitHub OAuth app at [github.com/settings/developers](https://github.com/settings/developers). Set the Authorization callback URL to match `GITHUB_OAUTH_REDIRECT_URI`.
    </Info>
  </Tab>

  <Tab title="Google">
    <ParamField path="GOOGLE_CLIENT_ID" type="string">
      Google OAuth 2.0 client ID.
    </ParamField>

    <ParamField path="GOOGLE_CLIENT_SECRET" type="string">
      Google OAuth 2.0 client secret.
    </ParamField>

    <ParamField path="GOOGLE_OAUTH_REDIRECT_URI" type="string">
      Callback URL registered in your Google Cloud Console.
    </ParamField>

    ```env
    GOOGLE_CLIENT_ID=your-client-id.apps.googleusercontent.com
    GOOGLE_CLIENT_SECRET=your-google-client-secret

    # Local development
    GOOGLE_OAUTH_REDIRECT_URI=http://localhost/api/auth/google/callback

    # Production
    GOOGLE_OAUTH_REDIRECT_URI=https://studio.yourcompany.com/api/auth/google/callback
    ```

    <Info>
      Create OAuth credentials at [console.cloud.google.com/apis/credentials](https://console.cloud.google.com/apis/credentials).
    </Info>
  </Tab>
</Tabs>

## AI / LLM Settings

<ParamField path="LITELLM_DEFAULT_MODELS" type="string" default="">
  Comma-separated list of model identifiers to offer users in the model selector. These must match models configured on your LiteLLM proxy.
</ParamField>

```env
# Single provider
LITELLM_DEFAULT_MODELS=claude-3-5-sonnet-20241022

# Multiple providers
LITELLM_DEFAULT_MODELS=gpt-4o-mini,claude-3-5-sonnet-20241022,qwen-3-235b-a22b-thinking-2507
```

**Supported model providers** (via LiteLLM):

| Provider | Example Models |
|----------|---------------|
| OpenAI | `gpt-4`, `gpt-3.5-turbo`, `gpt-4o-mini` |
| Anthropic | `claude-3-5-sonnet-20241022`, `claude-3-opus-20240229` |
| Custom / Self-hosted | `qwen-3-235b-a22b-thinking-2507` |

## Deployment Mode

<ParamField path="DEPLOYMENT_MODE" type="string" default="docker">
  Controls which container orchestration backend the orchestrator uses. Options: `docker` or `kubernetes`.
</ParamField>

```env
# Local development (Docker Compose + Traefik)
DEPLOYMENT_MODE=docker

# Production or Minikube testing (Kubernetes + NGINX Ingress)
DEPLOYMENT_MODE=kubernetes
```

<Info>
  The orchestrator automatically adapts its behavior based on this value. No code changes are needed to switch between modes. See the [Deployment Guide](/self-hosting/deployment) for details.
</Info>

## Container Runtime (Docker Mode)

These settings apply when `DEPLOYMENT_MODE=docker`.

<ParamField path="DEV_SERVER_BASE_URL" type="string" default="http://localhost">
  Base URL used for routing to user project containers in Docker mode.
</ParamField>

<ParamField path="APP_PORT" type="number" default="80">
  Host port for Traefik (HTTP).
</ParamField>

<ParamField path="BACKEND_PORT" type="number" default="8000">
  Host port for the backend API.
</ParamField>

<ParamField path="FRONTEND_PORT" type="number" default="5173">
  Host port for the Vite dev server.
</ParamField>

```env
DEPLOYMENT_MODE=docker
DEV_SERVER_BASE_URL=http://localhost
APP_PORT=80
BACKEND_PORT=8000
FRONTEND_PORT=5173
```

## Container Runtime (Kubernetes Mode)

These settings apply when `DEPLOYMENT_MODE=kubernetes`.

### Core Kubernetes Settings

<ParamField path="K8S_DEVSERVER_IMAGE" type="string" required>
  Docker image used for user project containers. For Minikube, use a local image name. For AWS EKS, use a full ECR URL.
</ParamField>

<ParamField path="K8S_IMAGE_PULL_SECRET" type="string" default="">
  Name of the Kubernetes image pull secret for private registries. Leave empty for local images (Minikube with `imagePullPolicy: Never`).
</ParamField>

<ParamField path="K8S_STORAGE_CLASS" type="string" default="tesslate-block-storage">
  Kubernetes StorageClass for user project PVCs.
</ParamField>

<ParamField path="K8S_PVC_SIZE" type="string" default="10Gi">
  Size of the PersistentVolumeClaim created for each user project.
</ParamField>

<Tabs>
  <Tab title="Minikube (local testing)">
    ```env
    DEPLOYMENT_MODE=kubernetes
    K8S_DEVSERVER_IMAGE=tesslate-devserver:latest
    K8S_IMAGE_PULL_SECRET=
    K8S_STORAGE_CLASS=standard
    ```
  </Tab>

  <Tab title="AWS EKS (production)">
    ```env
    DEPLOYMENT_MODE=kubernetes
    K8S_DEVSERVER_IMAGE=859561299901.dkr.ecr.us-east-1.amazonaws.com/tesslate-devserver:latest
    K8S_IMAGE_PULL_SECRET=ecr-credentials
    K8S_STORAGE_CLASS=tesslate-block-storage
    ```
  </Tab>
</Tabs>

### Snapshot / Hibernation Settings

These control the EBS VolumeSnapshot-based persistence system used in Kubernetes mode for hibernating and restoring user projects.

<ParamField path="K8S_SNAPSHOT_CLASS" type="string" default="tesslate-ebs-snapshots">
  VolumeSnapshotClass name for creating EBS snapshots.
</ParamField>

<ParamField path="K8S_SNAPSHOT_RETENTION_DAYS" type="number" default="30">
  Number of days to retain soft-deleted snapshots before permanent deletion.
</ParamField>

<ParamField path="K8S_MAX_SNAPSHOTS_PER_PROJECT" type="number" default="5">
  Maximum number of snapshots kept per project (for the Timeline UI).
</ParamField>

<ParamField path="K8S_SNAPSHOT_READY_TIMEOUT_SECONDS" type="number" default="90">
  Maximum time (in seconds) to wait for a VolumeSnapshot to become ready.
</ParamField>

<ParamField path="K8S_HIBERNATION_IDLE_MINUTES" type="number" default="10">
  Minutes of inactivity before a project is automatically hibernated (snapshot taken, namespace deleted).
</ParamField>

```env
K8S_SNAPSHOT_CLASS=tesslate-ebs-snapshots
K8S_SNAPSHOT_RETENTION_DAYS=30
K8S_MAX_SNAPSHOTS_PER_PROJECT=5
K8S_HIBERNATION_IDLE_MINUTES=10
```

### Networking and Ingress

<ParamField path="K8S_INGRESS_CLASS" type="string" default="nginx">
  Ingress class for user project Ingress resources.
</ParamField>

<ParamField path="K8S_WILDCARD_TLS_SECRET" type="string" default="">
  Name of the Kubernetes TLS secret containing the wildcard certificate. Leave empty for HTTP-only (Minikube).
</ParamField>

<ParamField path="K8S_ENABLE_POD_AFFINITY" type="boolean" default="true">
  When enabled, all containers in a multi-container project are scheduled on the same node. Required for sharing ReadWriteOnce PVCs.
</ParamField>

<ParamField path="K8S_ENABLE_NETWORK_POLICIES" type="boolean" default="true">
  When enabled, creates NetworkPolicy resources that enforce zero cross-project communication.
</ParamField>

```env
K8S_INGRESS_CLASS=nginx
K8S_WILDCARD_TLS_SECRET=tesslate-wildcard-tls
K8S_ENABLE_POD_AFFINITY=true
K8S_ENABLE_NETWORK_POLICIES=true
```

## S3 / Object Storage

Used in Kubernetes mode for legacy project storage. The current primary persistence mechanism uses EBS VolumeSnapshots, but S3 configuration is still relevant for asset storage.

<ParamField path="S3_BUCKET_NAME" type="string" default="tesslate-projects">
  S3 bucket name for project storage.
</ParamField>

<ParamField path="S3_ENDPOINT_URL" type="string" default="">
  S3 endpoint URL. Leave empty for native AWS S3. Set to a MinIO URL for local development or a DigitalOcean Spaces URL for DO deployments.
</ParamField>

<ParamField path="S3_REGION" type="string" default="us-east-1">
  AWS region for S3 signature calculation.
</ParamField>

<ParamField path="S3_ACCESS_KEY_ID" type="string">
  S3 access key. Not needed on AWS EKS when using IRSA (IAM Roles for Service Accounts).
</ParamField>

<ParamField path="S3_SECRET_ACCESS_KEY" type="string">
  S3 secret key. Not needed on AWS EKS when using IRSA.
</ParamField>

<Tabs>
  <Tab title="AWS S3 (with IRSA)">
    ```env
    S3_BUCKET_NAME=tesslate-projects-production-7761157a
    S3_REGION=us-east-1
    # No access keys needed; IRSA handles authentication.
    ```
  </Tab>

  <Tab title="MinIO (Minikube local)">
    ```env
    S3_ENDPOINT_URL=http://minio.minio-system.svc.cluster.local:9000
    S3_BUCKET_NAME=tesslate-projects
    S3_ACCESS_KEY_ID=minioadmin
    S3_SECRET_ACCESS_KEY=minioadmin
    ```
  </Tab>

  <Tab title="DigitalOcean Spaces">
    ```env
    S3_ENDPOINT_URL=https://nyc3.digitaloceanspaces.com
    S3_BUCKET_NAME=your-space-name
    S3_REGION=nyc3
    S3_ACCESS_KEY_ID=your-access-key
    S3_SECRET_ACCESS_KEY=your-secret-key
    ```

## Logging

<ParamField path="LOG_LEVEL" type="string" default="INFO">
  Application logging level. Options: `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`.
</ParamField>

```env
# Development (verbose output)
LOG_LEVEL=DEBUG

# Production (normal output)
LOG_LEVEL=INFO
```

Log format: `%(asctime)s - %(name)s - %(levelname)s - %(message)s`

Key loggers include `app.main`, `app.services.orchestration.kubernetes_orchestrator`, `app.agent.stream_agent`, and `app.routers.*`.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Invalid or missing SECRET_KEY">
    **Symptom:** The orchestrator crashes on startup with a key-related error.

    **Fix:** Generate a new key and update `.env`:
    ```bash
    python3 -c "import secrets; print(secrets.token_urlsafe(32))"
    ```
    Then restart: `docker compose restart orchestrator`
  </Accordion>

  <Accordion title="Database connection failed">
    **Symptom:** Errors about PostgreSQL not being accessible.

    **Fix:**
    ```bash
    # Check if postgres container is running
    docker compose ps postgres

    # Check logs for details
    docker compose logs postgres

    # Restart the database
    docker compose restart postgres
    ```
    Verify that `DATABASE_URL` in `.env` matches the actual database credentials.
  </Accordion>

  <Accordion title="AI models not appearing or returning errors">
    **Symptom:** The model selector is empty, or chat returns "API key not found."

    **Fix:**
    1. Verify `LITELLM_API_BASE` points to a running LiteLLM instance.
    2. Verify `LITELLM_MASTER_KEY` is correct.
    3. Check that `LITELLM_DEFAULT_MODELS` lists valid model names.
    4. Restart the orchestrator: `docker compose restart orchestrator`
  </Accordion>

  <Accordion title="OAuth redirect errors">
    **Symptom:** After clicking "Login with GitHub/Google," you see a redirect error.

    **Fix:** Ensure the callback URL registered with the OAuth provider matches `GITHUB_OAUTH_REDIRECT_URI` or `GOOGLE_OAUTH_REDIRECT_URI` exactly, including the protocol (`http` vs `https`) and path.
  </Accordion>
</AccordionGroup>

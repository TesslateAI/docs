## What the Assets panel does

The Assets panel is where binary files live. Images, fonts, videos, PDFs, and other non-code files that your app needs at runtime. The panel uploads, organizes, previews, and gives you a direct URL for each asset.

Assets are stored in the project database as binary data and written to the container filesystem or persistent volume at the path you specify. Your running app serves them over the dev server URL.

## Opening the panel

Open the Assets panel from the tool dock in the project builder. It lives in `panels/AssetsPanel.tsx` and composes `AssetUploadZone`, `DirectoryTree`, and `AssetCard` renderers.

The panel has two view modes: **grid** and **list**. Grid shows thumbnails for images. List shows a dense sortable table with filename, size, MIME type, and upload time.

## Uploading

<Steps>
  <Step title="Drop or click">
    Drag files onto the upload zone or click to open a file picker. Multiple files upload in parallel.
  </Step>
  <Step title="Pick a directory">
    Default is `public`. Override with the directory picker if you are uploading into a subdirectory.
  </Step>
  <Step title="Wait for progress">
    Upload progress shows per file. Size limits are 10MB per file, 50MB per upload batch by default.
  </Step>
  <Step title="Use in code">
    After upload, copy the asset's URL from the card and paste it into your code.
  </Step>
</Steps>

## File types

| Category | Extensions | Notes |
|----------|------------|-------|
| **Images** | PNG, JPG, JPEG, SVG, GIF, WebP, AVIF | Dimensions and thumbnails generated |
| **Fonts** | TTF, OTF, WOFF, WOFF2 | Served with correct MIME types |
| **Video** | MP4, WebM, MOV | Stream-friendly, no transcoding |
| **Audio** | MP3, WAV, OGG | Same direct serve |
| **Documents** | PDF, TXT, Markdown | Downloadable or rendered in-browser |
| **Data** | JSON, CSV, XML | Usable as seed data |

Validation runs client-side (`validateFile` in `types/assets.ts`) and server-side. Unsupported or oversized files are rejected with a toast.

## Directory tree

The directory tree is the `DirectoryTree` component. It shows nested folders with expand/collapse and lets you create new directories inline.

- **Create a folder** click the + button on any node
- **Rename** double-click the folder name
- **Move assets** drag asset cards onto a folder to move them
- **Delete** kebab menu on the folder (only works if the folder is empty)

## Per-asset actions

Each asset card has a right-click menu (or a kebab in list view):

- **Copy URL** puts the public URL on the clipboard
- **Copy markdown** `![alt](url)` snippet
- **Rename** inline input for the new filename
- **Move** picker for the target directory
- **Download** download the asset to your machine
- **Delete** remove from the project (permanent)

## Direct URLs

Every asset has a URL served by the project's dev server:

```
http://{container}.{slug}.localhost/public/hero.png          # Docker
https://{container}.{slug}.{domain}/public/hero.png          # Kubernetes
http://127.0.0.1:{port}/public/hero.png                      # Desktop local
```

Use them in your code like any static file:

```tsx
<img src="/public/hero.png" alt="Hero" />
```

The dev server picks up new uploads immediately. No restart required.

## Search

The panel top bar has a search input. Filter by filename, directory, or MIME type. Combines with the directory selection to scope the search.

## Assets vs code files

Assets live in the `Asset` model with binary storage, metadata (MIME, size, dimensions), and directory tracking. Code files live in `ProjectFile` or on the volume directly. The two are separate because code is text-oriented and tracked in git while assets are typically binary and tracked as blobs.

<Info>
  If you want an asset to ship in git, drop it in `public/` and commit it through the Git panel. If you want it platform-managed with UI tooling, upload through the Assets panel.
</Info>

## Agent access

The agent can read assets (URLs are visible in the project tree and the agent can `web_fetch` them) but currently cannot upload. For agent-driven asset creation (like generated images), have the agent produce the file in the project directory through `write_file` and the asset pipeline will ingest it on the next scan.
